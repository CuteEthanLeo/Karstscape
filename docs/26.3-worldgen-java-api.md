## 要点（中文摘要）

**自定义密度函数 `karstscape:tower_field` 怎么写**
- 实现 `DensityFunction` 的 5 个抽象方法：`compileSampler`、`rewriteChildren`、`range`、`domainAxes`、`codec`。用 `record` 实现可自动获得值相等（编译器按函数对象做缓存去重）。
- 注册：`Registry.register(BuiltInRegistries.DENSITY_FUNCTION_TYPE, Identifier.fromNamespaceAndPath("karstscape","tower_field"), CODEC)`，用普通 `MapCodec`（26.3 已没有 `KeyDispatchDataCodec`）。在 Fabric `onInitialize` 中注册是否早于注册表冻结：**未核实，M2 第一步实测**。
- **拿世界种子**：`compileSampler(CompileContext ctx)` 里调用 `ctx.createRandom(Identifier)`，得到由世界种子和该 id 哈希出的确定性 `RandomSource`（`RandomState.java:91`）。这是原版 `old_blended_noise` 的同款做法，**不需要 mixin，也不读全局状态**，满足 SPEC §3.2 的“种子绑定”要求。
- 求值改成了**批量体积采样**：`DensitySampler.sampleVolume(ctx, buffer, volume)`（整块 16×H×16，步长 1）加单点 `sampleValue`。两条路径结果必须一致；采样器会被多线程共享，必须不可变。
- 26.3 统一为单精度 `float`。

**陡壁不被插值抹平**
- 只有 `interpolated` 节点**内部**的子树按 cell 角点采样；放在它外面、通过 `max`/`add` 组合的分支对整块体积逐方块求值（原版的 `beardifier` 就是这样放的）。所以 `max(interpolated(平原地形), tower_field)` 能保住垂直侧壁。

**2D 缓存（SPEC 里的 `cache_2d`/`flat_cache` 已不存在）**
- 把 `domainAxes()` 声明为 X|Z（不含 Y），编译器会自动套上 `SliceFunction`：每列只算一次，再沿 y 广播。所以可以把石峰拆成“2D 峰顶高度 `tower_top`（domainAxes=X|Z）”和“`(tower_top − y) × k`”两部分，前者自动按列缓存。
- 内置 `cache` 只在一个区块任务内按“上一个体积 + 上一个点”缓存，模组拿不到不冲突的 cache id，不要自己造缓存单元。
- `range()` 必须是真实上下界：`min`/`max` 会在编译期按范围丢分支、点查询时按范围短路；`find_top_surface` 会在维度高度之外采样，所以采样器内部要把 y 夹到 [minY, maxY]。
- 体积路径下 `max`/`mul` 两边都会算，遮罩为 0 的地方石峰分支照样被计算；需要提前退出只能在自定义采样器内部做（性能预算相关）。

**区域遮罩与群系同源**
- 群系查找用的 6 个气候参数就来自 noise_router：`temperature`、`vegetation`→humidity、`continents`→continentalness、`erosion`、`depth`、`ridges`→weirdness（`NoiseRouter.java:33-41`）。`final_density` 可以直接引用同一批 `minecraft:overworld/continents` 等函数 id，因此遮罩和群系参数盒能用同一组数值。
- `multi_noise_biome_source_parameter_list` 注册表只认硬编码的 `minecraft:overworld` / `minecraft:nether` 预设；**要加自定义群系，世界预设里的 biome_source 必须用内联 `biomes` 列表**（底稿是 `reports/biome_parameters/minecraft/overworld.json`）。

**世界预设、命令、客户端兼容**
- 专用服务器 `level-type` 接受任何已注册的预设 id（包括 `karstscape:karst_only`）；未知 id 只记一条 WARN 并回落到 `minecraft:normal`，不会报错——**自测脚本必须检查实际用到的预设，不能只看无报错**。
- 命令：Fabric `net.fabricmc.fabric.api.command.v2.CommandRegistrationCallback`；OP 权限用 `.requires(Commands.hasPermission(Commands.LEVEL_GAMEMASTERS))`（26.3 已没有 `hasPermission(int)`）。
- `/locate biome` 的实现可复用来写 `/karstscape find`；无需生成区块即可取地表高度的方法见报告二 §4。
- 原版只把 `SYNCHRONIZED_REGISTRIES`（含 biome，不含 density_function_type / noise_settings）同步给客户端，所以自定义密度函数类型不会发给客户端。原版客户端能否接受自定义群系数据：**未实测，M1 用原版启动器验证**。

### 1. The DensityFunction interface (df/DensityFunction.java)

A custom type has five abstract methods to implement. Everything else is either a default helper (:57-149) or the static `axesFrom` (:39-45).

#### `DensitySampler compileSampler(DensityFunction.CompileContext context)` (:47)

**[CORRECTED] Who calls it:**
- The compiler calls it directly only in two places:
  - on the optimized root (df/DensityFunctionCompiler.java:39-40);
  - on each newly prepared cache input (:58-59).
- Every other node is compiled by its parent's `compileSampler` (df/op/BinaryFunction.java:22-23, df/op/SliceFunction.java:32, df/op/InterpolatedFunction.java:28).
- Root samplers are memoized in a ConcurrentHashMap keyed by the root DensityFunction (df/DensityFunctionCompiler.java:14,31-33). A non-cached node reachable from several roots is therefore compiled once per root.
- BinaryFunction compiles both children before MIN/MAX may drop one (df/op/BinaryFunction.java:22-23 vs :70-97).
- Consequence: `compileSampler` must be cheap and deterministic.

There is one compiler per RandomState (lg/RandomState.java:37,72-99).

**CompileContext** offers three methods:
- `createNoiseSampler(Holder<NormalNoise>)` (:157).
- `createRandom(Identifier)` (:159). Implementation: `RandomState.this.random.fromHashOf(seed)` (lg/RandomState.java:91), where `random` is forked from the world seed (:66).
  - **[CORRECTED]** Exception: when `useLegacyRandom` is set and the id is `BlendedNoise.NOISE_SEED` (`minecraft:terrain`), it returns `new LegacyRandomSource(worldSeed)` instead (lg/RandomState.java:74-76,91; synth/BlendedNoise.java:38). This does not affect `karstscape:*` ids.
  - `fromHashOf` builds a fresh, deterministic RandomSource from the name's hash XOR the seed state (lg/PositionalRandomFactory.java:13-17; lg/XoroshiroRandomSource.java:129-132; lg/LegacyRandomSource.java:71-74). It is therefore safe to call on every compile.
- the deprecated `createEndIslandRandom()` (:161-162).

Supporting facts:
- Vanilla precedent: BlendedNoise calls `context.createRandom(NOISE_SEED)` (synth/BlendedNoise.java:93-95).
- `RandomSource.nextLong()` exists (util/RandomSource.java:49).

#### `DensityFunction rewriteChildren(DfRewriteRule rule)` (:49)
- Route every child through `rule.rewrite(child)`.
- Return `this` if nothing changed, otherwise a new instance (df/op/CacheFunction.java:21-24; df/op/BinaryFunction.java:118-122).
- Leaves return `this` (df/generator/ConstantFunction.java:39-42).

#### `Interval range()` (:51)
- Float min/max (util/Interval.java:11-12).
- `Interval.of` (:19) throws if max<min or either bound is NaN (:20-26).
- The bounds must be true bounds (see section 6).

#### `@Axes int domainAxes()` (:53)
- AXIS_X=1, AXIS_Y=2, AXIS_Z=4, NO_AXES=0, ALL_AXES=7 (:33-37).

#### `MapCodec<? extends DensityFunction> codec()` (:55)
- Dispatch: `BuiltInRegistries.DENSITY_FUNCTION_TYPE.byNameCodec().dispatch(DensityFunction::codec, identity)` (df/DensityFunctions.java:43-45).
- Child fields use `DensityFunction.CODEC`, which accepts a registry reference or an inline function (df/DensityFunction.java:21-32). Bare numbers decode to constants (df/DensityFunctions.java:46-52).
- Float fields conventionally use `NOISE_VALUE_CODEC`, range ±1e6 (df/DensityFunctions.java:41-42; df/generator/ConstantFunction.java:16).

#### DensitySampler (df/DensitySampler.java)
- Two required methods: `sampleVolume(SamplerContext, DensityBuffer, DensityVolume)` (:4) and `float sampleValue(SamplerContext, int, int, int)` (:23).
- Helper `sampleVolumeNaive` loops z, x, y (:6-21).

### 2. Evaluation model: batched volumes plus a point path

**Terrain fill:**
- A single `finalDensity.sampleVolume(volume)` call per chunk (lg/NoiseBasedChunkGenerator.java:397-399).
- The volume is 16 × height × 16 with step 1 (:105-108; df/DensityVolume.java:29-31).
- Height-column queries use 1×H×1 (:177,189-191).

**Strided volumes exist, so samplers must honour `stepBlockX/Y/Z`:**
- Aquifer builds a (4,1,4) volume for its `surfaceLevel` function (lg/Aquifer.java:172-181). **[CORRECTED]** This is not final_density.
- MultiNoiseBiomeSource builds a (4,4,4) volume for the climate functions (biome/MultiNoiseBiomeSource.java:75-86).
- Interpolation requests cell-corner volumes (df/op/InterpolatedFunction.java:106-116).

**Point queries also happen:**
- Aquifer samples other router functions per point (lg/Aquifer.java:169,406,510,517,544,558).
- FindTopSurface probes `density.sampleValue` (df/op/FindTopSurfaceFunction.java:92-93).
- `sampleValue` must therefore agree with `sampleVolume`.

**DensityVolume** (df/DensityVolume.java):
- A 9-int record (:6). The constructor rejects non-positive size or step (:9-27).
- `blockX(i) = minBlockX + i*stepBlockX` (:37-47).
- Index layout is Y fastest: `y + (x + z*sizeX)*sizeY` (:33-35).

**DensityBuffer** (df/DensityBuffer.java):
- Exposes set/setRange/addTo/get/fill/copyFrom (:6,18-44).
- Use `size()`, not capacity: pooled buffers can be larger than their size (df/ScopedDensityBuffer.java:8-11; df/DensityBuffer.java:46-52).

**Scratch buffers:**
- Acquire with `context.acquireBuffer(volume)` (df/SamplerContext.java:36-38) and close with try-with-resources (df/op/BinaryFunction.java:154).
- The pool comes from RandomState, one per NoiseChunk (lg/NoiseChunk.java:29,39).

**Precision:**
- Values and Interval bounds are float (df/DensitySampler.java:23; df/DensityBuffer.java:6; util/Interval.java:11-12).
- Coordinates are int.
- Internals may use double (df/generator/NoiseFunction.java:94).

**SamplerContext** (df/SamplerContext.java):
- User fields (:14,28-34).
- Arena (:15,36-38).
- Optional cache cells (:16,21).
- NoiseChunk builds it with `setUserFields/useBufferArena/enableCaches` (lg/NoiseChunk.java:38-40), so for terrain the cache lifetime is one chunk or column job. Other contexts exist, e.g. lg/NoiseBasedChunkGenerator.java:117.

**Context-bound samplers:**
- ContextBoundSampler reads from user fields, otherwise uses the fallback (df/ContextBoundSampler.java:5-16).
- Used by blend_alpha, blend_offset and beardifier (df/generator/SimpleDensityFunction.java:26-30; keys at lg/NoiseChunk.java:30-35).

**Bound samplers:**
- `DensitySampler.Bound.sampleVolume(volume)` allocates from the context arena (df/DensitySampler.java:29-42).
- RandomState hands out Bound samplers (lg/RandomState.java:102-113).

**Threading:**
- Terrain runs on `Util.backgroundExecutor()` (lg/NoiseBasedChunkGenerator.java:353,388).
- The compiler uses a ConcurrentHashMap and a lock (df/DensityFunctionCompiler.java:14,23,36-43).
- **[INFERENCE]** Compiled samplers are shared across threads, so they should be immutable, with per-chunk state kept only in SamplerContext.

### 3. Caching

**How the compiler handles `minecraft:cache`:**
- `minecraft:cache` is `CacheFunction(input)` (df/op/CacheFunction.java:10-13). Compiling it directly throws (:16-18).
- The compiler swaps it for a PreparedCache (df/DensityFunctionCompiler.java:20).
- Dedupe is by `cache.input()` (the raw, un-rewritten input) in a compiler-wide HashMap (:24,46-53).
- Each new cache gets `id = nextCacheId++`. Its input is run through the full optimizer, including SLICE_UNIFORM_AXES(7) (:56-60).
- CachingDensitySampler forwards to `sampleVolumeCached` / `sampleValueCached` (df/CachingDensitySampler.java:3-12).
- The CacheId record is unused; its only occurrence is the declaration (df/CacheId.java:3).

**Cache semantics** (df/SamplerContext.java):
- One CacheCell per id, holding the last volume, its buffer and one (key, value) pair (:129-134).
- Volume path: re-sample when the volume changes, then copy out (:58-75). This is a "last volume" cache.
- Point path:
  - first the single value keyed by `BlockPos.asLong(x,y,z)` (:83-86);
  - then a lookup in the cached volume (:88-93);
  - else compute and store (:95-98).
- With caches disabled it always calls through (:40-43,60-61,79-81).

**Dimensionality comes from the volume the cache receives.**
- A function with domainAxes = X|Z gets wrapped in `SliceFunction(Y, 0, f)` (df/DfRewriteRule.java:38-40,53-55).
- YSampler samples `sizeX×1×sizeZ` at y=0 and broadcasts each column with `setRange` (df/op/SliceFunction.java:141-161).
- The point path uses y = 0 (:165-167), so the cache key is (x,0,z).

**Per-column towerTop: two options.**

(a) A 2D type (domainAxes = 5), combined in data, e.g. `mul(sub(cache(karstscape:tower_top), "minecraft:y"), k)`.
- `minecraft:y` is a Y gradient (vanilla density_function/y.json).
- `sub` is a BinaryFunction type (df/DensityFunctions.java:78-80; df/op/BinaryFunction.java:381).
- Gradient is never sliced (df/DfRewriteRule.java:72-74).
- The 2D part is sampled at 16×1×16 per chunk fill and broadcast.
- Add `cache` only if the function is referenced more than once.

(b) A single 3D type (domainAxes = 7) that computes towerTop once per (x,z) in `sampleVolume` and writes the Y run.
- Precedent: EndIslandFunction with setRange (df/generator/EndIslandFunction.java:74-85).
- FindTopSurface wraps its sampler in `SliceFunction.YSampler(sampler, 0)` (df/op/FindTopSurfaceFunction.java:28-34).

**[CORRECTED] Own cache cells:**
- `sampleVolumeCached` / `sampleValueCached` are package-private (df/SamplerContext.java:58,77).
- However, CachingDensitySampler is a public record with a public constructor (df/CachingDensitySampler.java:3), so a mod could construct one.
- What a mod cannot do is get a non-colliding id: `nextCacheId` is private (df/DensityFunctionCompiler.java:25,57).
- So use CacheFunction / `DensityFunctions.cache(f)` (df/DensityFunctions.java:162-164).

### 4. `interpolated` and siblings outside it

**Configuration:**
- `InterpolatedFunction(input, cellSizeXz, cellSizeY)` reads `cell_size_xz` and `cell_size_y` as POSITIVE_INT (df/op/InterpolatedFunction.java:16-24).
- NoiseSettings is just `(minY, height)` (lg/NoiseSettings.java:10).

**Sampler behaviour:**
- Grid-aligned volumes pass through (:55-61).
- Step 1 goes through `sampleWithBlockStep`: a corner volume (:96-119), then a trilinear fill (:121-197).
- Other strides go through a temporary block volume (:62-66,69-94).
- **[CORRECTED]** Point path:
  - exactly on a corner, it calls the input directly (:204-205);
  - otherwise it samples a 2×2×2 volume and uses lerp3 (:208-225).

**Tiling:** TilingMode belongs to `gradient` (df/TilingMode.java:6-9; df/generator/GradientFunction.java:19,24,45-53).

**Siblings outside the interpolated node:**
- Binary ops sample both children on the same incoming volume (MaxSampler, df/op/BinaryFunction.java:290-305).
- For the terrain fill that volume is step 1, so a max/add sibling outside `interpolated` is evaluated at every block (lg/NoiseBasedChunkGenerator.java:105-108,397-399).
- Only the subtree under `interpolated` sees corner volumes (df/op/InterpolatedFunction.java:118-119).

**Vanilla precedent:** overworld final_density is `add(min(squeeze(interpolated{4,8}(...)), overworld/caves/noodle), beardifier)`, with beardifier outside the interpolation (vanilla density_function/overworld/final_density.json).

**Consequence:** tower_field placed inside `interpolated` would only be sampled at cell corners.

### 6. Rewrite and optimisation passes

**The optimizer:**
- It is `sequence(inline + cache-dedupe rule (recursive via rewriteChildren), SLICE_UNIFORM_AXES)` (df/DensityFunctionCompiler.java:16-22).
- INLINE_REFERENCE unwraps HolderHolder (df/DfRewriteRule.java:11).

**SLICE_UNIFORM_AXES = SliceUniformAxes(7)** (:12,26-58):
- **[CORRECTED]** It fires whenever a node's axes differ from the parent's (:34).
- It recurses with the node's own axes, then wraps the node in slices for `parent & ~node` (:38-40), in the order X, Z, Y, at coordinate 0 (:45-55).
- It applies to the root and to every cache input (df/DensityFunctionCompiler.java:58).
- It skips Constant and Gradient (df/DfRewriteRule.java:72-74).
- It does not double-slice (:60-70).

**Consequences for a custom type:**

(i) `rewriteChildren` must route every child through the rule. Otherwise:
- a child CacheFunction reaches `compileSampler` and throws (df/op/CacheFunction.java:16-18);
- children are not inlined or sliced.

(ii) Value equality is **[INFERENCE] recommended, not strictly required**. The sampler map and cache-dedupe map are keyed by DensityFunction (df/DensityFunctionCompiler.java:14,24,47). Identity equality would only defeat memoization and dedupe. A record gives value equality for free.

(iii) `domainAxes()` must be truthful. Omitting Y while depending on y gets the function sliced at y = 0.

(iv) `range()` must be a true bound:
- MIN/MAX drop a branch at compile time if the ranges do not overlap (df/op/BinaryFunction.java:70-79,89-97).
- MaxSampler/MinSampler short-circuit point queries using the right operand's max/min (:104,310; :85,334).

(v) **[CORRECTED]** No generic constant folding was found. Only per-op sampler specialisation on ConstantFunction operands, found in:
- BinaryFunction (df/op/BinaryFunction.java:26-69,80-86,99-104);
- RangeChoice (df/op/RangeChoiceFunction.java:32-33);
- Lerp (df/op/LerpFunction.java:31-36);
- Pow (df/op/PowFunction.java:25-28);
- Round (df/op/RoundFunction.java:29-31).

**Performance:**
- The volume path evaluates both branches of max, mul and range_choice (df/op/BinaryFunction.java:292-305,340-350; df/op/RangeChoiceFunction.java:87-104).
- Only point paths short-circuit (df/op/BinaryFunction.java:310,354-355; df/op/RangeChoiceFunction.java:107-111). MulSampler short-circuits only when the left operand is 0.
- So the tower branch is computed over the whole chunk volume even where the mask is 0. **[INFERENCE]** Any early-out must be inside the custom sampler.

### 7. The 2D-only marker

**The marker:** `domainAxes()` without AXIS_Y, i.e. X|Z = 5 (df/DensityFunction.java:33-37,53).

**Vanilla examples:**
- noise with y_scale == 0 (df/generator/NoiseFunction.java:66-77);
- EndIsland returns 5 (df/generator/EndIslandFunction.java:57-60);
- blend_alpha and blend_offset return 5 (df/generator/SimpleDensityFunction.java:47-52);
- FindTopSurface masks with `& -3` (df/op/FindTopSurfaceFunction.java:48-51);
- Slice removes its axis (df/op/SliceFunction.java:65-68);
- Cache, Interpolated and HolderHolder propagate their input's axes (df/op/CacheFunction.java:31-34; df/op/InterpolatedFunction.java:42-45; df/DensityFunctions.java:378-381);
- PreparedCache keeps the input's axes (df/DensityFunctionCompiler.java:60,63).

**How vanilla exploits it:** YSampler samples once per column and broadcasts (df/op/SliceFunction.java:141-167). An X+Z double slice collapses to XzSampler (:28-50,107-138).

**Climate mask:** vanilla `overworld/continents` is `cache(noise{y_scale 0.0, shift_x, shift_z})`. shift_x and shift_z are `cache(shift_a)` and `cache(shift_b)`, whose axes are 5 (df/generator/ShiftNoiseFunction.java:59,76-77; :86,127-128). So continents is a cached 2D function.

### 6. Determinism and threading

**Parallelism**
- `buildTerrain` runs on the shared background executor (NoiseBasedChunkGenerator.java:353,388).
- One RandomState is shared by all threads:
  - samplers in a ConcurrentHashMap plus a compile lock (DensityFunctionCompiler.java:14,23,35-44);
  - noise instances and positional randoms in ConcurrentHashMaps (RandomState.java:69-70,121,125).
- Custom DensitySamplers must therefore be immutable and stateless. Compilation can happen lazily on any worker thread and may run more than once for the same type (see §1).

**Per-chunk state**
- Lives in `SamplerContext`, one per NoiseChunk (NoiseChunk.java:38-40). Its cache cells are plain arrays (SamplerContext.java:16,40-56).
- Use `context.acquireBuffer(volume)` with try-with-resources (SamplerContext.java:36-38; ScopedDensityBuffer.java:33-38).
- `DensityBufferPool` is an unsynchronised ArrayList (DensityBufferPool.java:13,19-53).
  - It is handed out per NoiseChunk under a lock (RandomState.java:141-161).
  - It is aged via `ServerLevel` → `randomState().garbageCollect()` (ServerLevel.java:474; RandomState.java:163-174).
- `SamplerContext.EMPTY_UNCACHED` is a global, cache-less context on the `GLOBAL` arena (SamplerContext.java:12; DensityBufferArena.java:4-13).

**Cache semantics**
- `cache` holds one volume per cache id per context and recomputes on a volume mismatch (SamplerContext.java:58-75).
- Single values come from a last-position key or from the cached volume (SamplerContext.java:77-99; CachingDensitySampler.java:3-13).
- Cached functions must therefore be a pure function of (x,y,z) for a given RandomState.
- Caches are deduplicated by `cache.input()` equality and samplers are keyed by function equality (DensityFunctionCompiler.java:31-33,46-54). Records give correct equals/hashCode.

**Order-dependence elsewhere**
- Aquifer cell positions come from `positionalRandomFactory.at(gridX,gridY,gridZ)`, cached per aquifer instance (Aquifer.java:241-251).
- Carvers start from `generateUniqueSeed()` but are reseeded with `setLargeFeatureSeed(seed+index, x, z)` before use (NoiseBasedChunkGenerator.java:236,260).
- The only RandomSource use in the densityfunction package is EndIslandFunction at compile time (generator/EndIslandFunction.java:46-48). BlendedNoise also consumes its random only at compile time (BlendedNoise.java:93-107).
- So a custom type should consume its RandomSource only inside `compileSampler`, in a fixed order, and hash `(salt, cellX, cellZ)` at sample time.

- Mapping: router `vegetation` becomes humidity, `continents` becomes continentalness, `ridges` becomes weirdness. Temperature, erosion and depth keep their names.
- The 26.3 router codec has exactly 8 fields: temperature, vegetation, continents, erosion, depth, ridges, chunk_surface_level, final_density (NoiseRouter.java:9-31).

#### How samplers are built and evaluated
- Each sampler is `RandomState.samplersWithContext(ctx).get(df)`, which is `getSampler(function).bind(context)` (net/minecraft/world/level/levelgen/RandomState.java:102-114). `createClimateSampler(ctx)` wraps it (RandomState.java:116-118).
- **Per-point path:** `Sampler.sample(quartX,quartY,quartZ)` converts with `QuartPos.toBlock` (quart<<2, net/minecraft/core/QuartPos.java:20-22). It calls `sampleValue` once per climate value at block coordinates that are multiples of 4, then `Climate.target(...)` (Climate.java:464-476). `createResolver` uses this path (MultiNoiseBiomeSource.java:61-63).
- **Batched chunk path:** `createResolverForChunk` builds a `DensityVolume(..., 4,4,4)`. The 4,4,4 are the stepBlock args (densityfunction/DensityVolume.java:6-9). It fills six unpooled DensityBuffers with `sampleVolume`, then calls Climate.target per lookup (MultiNoiseBiomeSource.java:75-95).

#### Quantization
- `quantizeCoord(f) = (long)(f * 10000.0F)`; unquantize divides by 10000 (Climate.java:64-70).
- `target(...)` quantizes all six values (Climate.java:30-36).
- TargetPoint is 6 longs. `toParameterArray` appends a 7th value of 0 (Climate.java:479-483).

#### Biome pick
- `getNoiseBiome(target)` calls `parameters().findValue(target)` (MultiNoiseBiomeSource.java:98-101).
- findValue calls `findValueIndex(target, RTree.Node::distance)`, an R-tree search (Climate.java:157-158, 180-186).
- **[corrected]** The metric is `Node.distance`: the sum of squared per-axis `Parameter.distance` over 7 dimensions (Climate.java:114-118, 406-414). Offset is the 7th dimension, `Parameter(offset, offset)` (Climate.java:221-224), and the target's 7th value is 0, so the result equals Σ dist² + offset². `ParameterPoint.fitness` computes the same value (Climate.java:211-219), but only `findValueBruteForce` uses it (Climate.java:162-178).

#### Codec forms
- Codec accepts either form: `Codec.mapEither(DIRECT_CODEC, PRESET_CODEC)` (MultiNoiseBiomeSource.java:26).
- DIRECT_CODEC = `Climate.ParameterList.codec(Biome.CODEC.fieldOf("biome")).fieldOf("biomes")` (MultiNoiseBiomeSource.java:21-22).
  - The list must be non-empty. Each element has a "parameters" ParameterPoint and a "biome" field in the same object (Climate.java:129-137).
  - ParameterPoint fields: temperature, humidity, continentalness, erosion, depth, weirdness, and a **required** offset, a float in 0..1 (Climate.java:198-209).
  - Each Parameter is a bare float, a `[min,max]` array, or `{"min":..,"max":..}` (net/minecraft/util/ExtraCodecs.java:278-301). Values must be in -2..2 and min must be ≤ max (Climate.java:78-87).
- `preset` is a holder in the multi_noise_biome_source_parameter_list registry (MultiNoiseBiomeSource.java:23-25; MultiNoiseBiomeSourceParameterList.java:28-30).
  - Registry entries only accept `{"preset": id}`, and id must be the hard-coded minecraft:nether or minecraft:overworld. Anything else fails with "Unknown preset" (net/minecraft/world/level/biome/MultiNoiseBiomeSourceParameterList.java:24-27, 76-82; reference/vanilla-26.3/data/minecraft/worldgen/multi_noise_biome_source_parameter_list/overworld.json:1-3).
  - So custom climate tables must use the inline "biomes" form.
- Inline shape: `"biome_source":{"type":"minecraft:multi_noise","biomes":[{"biome":"karstscape:x","parameters":{"temperature":[-1,1],"humidity":0,"continentalness":{"min":0.3,"max":1},"erosion":[-1,1],"depth":0,"weirdness":[-1,1],"offset":0}}]}`
- Vanilla's preset form is in reference/vanilla-26.3/data/minecraft/worldgen/world_preset/normal.json:6-9.

### 2. Can final_density read the same climate functions? Yes.

#### Vanilla data (all files under reference/vanilla-26.3/data/minecraft/worldgen/density_function/overworld/ unless noted)
- The router uses registry references: continents "minecraft:overworld/continents", erosion "minecraft:overworld/erosion", ridges "minecraft:overworld/ridges", plus temperature, vegetation and depth (reference/vanilla-26.3/data/minecraft/worldgen/noise_settings/overworld.json:111-120).
- Vanilla terrain already reads those same functions:
  - offset.json: continents (line 17), erosion (48), ridges_folded (54).
  - factor.json: continents, erosion, ridges (12, 23, 29).
  - **[corrected]** jaggedness.json: continents (12), erosion (23), ridges_folded (29), ridges (45).
  - ridges_folded.json: overworld/ridges (11).
  - sloped_cheese.json: depth, jaggedness, factor (13, 18, 31).
  - final_density.json: sloped_cheese (39, 44).
  - depth.json: a y gradient plus overworld/offset (1-12), so depth is y-dependent.
- continents.json, erosion.json and ridges.json are each `minecraft:cache` wrapping `minecraft:noise` with xz_scale 0.25 and y_scale 0.0 (lines 1-11 of each).
- temperature.json and vegetation.json are bare `minecraft:noise` (lines 1-8).

#### How references resolve in code
- `DensityFunction.CODEC` is a registry-holder codec. References become `DensityFunctions.HolderHolder` (net/minecraft/world/level/levelgen/densityfunction/DensityFunction.java:21-32; corrected from 20-29).
- The compiler's optimizer inlines references with `DfRewriteRule.INLINE_REFERENCE` (densityfunction/DfRewriteRule.java:11; densityfunction/DensityFunctionCompiler.java:16-22).
- It reuses one PreparedCache per `cache.input()` (DensityFunctionCompiler.java:46-54).
- It memoizes samplers per DensityFunction (DensityFunctionCompiler.java:14, 31-33).

#### Shared state between biomes and terrain
- Biome lookup and terrain share one RandomState compiler and its noise instances (RandomState.java:72-99, 116-122, 132-134).
- Terrain gets final_density through NoiseChunk, which calls `randomState.samplersWithContext(...)` (net/minecraft/world/level/levelgen/NoiseChunk.java:38-40; NoiseBasedChunkGenerator.java:397).
- So a mask built from `minecraft:overworld/continents` / `erosion` compiles to the same sampler the biome lookup uses, and it is seed-deterministic.
- **[added]** Cached *values* are not shared. `CachingDensitySampler` delegates to the `SamplerContext` (densityfunction/CachingDensitySampler.java:5-12; SamplerContext.java:58-99). Biome resolution and terrain use different contexts (BiomeSource.java:157-160; ChunkGenerator.java:138; NoiseChunk.java:38-40).
- **[added]** The per-point cache key is the full 3D `BlockPos.asLong(x,y,z)` (SamplerContext.java:83). Volume caching is keyed by `DensityVolume` equality (SamplerContext.java:63).
- Caveat: biomes sample at quart points, multiples of 4 (Climate.java:465-467). Terrain fills a per-block 16 x height x 16 volume (NoiseBasedChunkGenerator.java:105-108, 399-409). So mask edges and biome edges can differ. Block-level biome lookups also go through BiomeManager's fuzzy zoom (world/level/biome/BiomeManager.java:35-58, 89-101). The maximum offset is NOT VERIFIED.

#### Seeding hook for a custom DF type (added; the original report had no claim here)
- `DensityFunction.compileSampler(CompileContext)` (DensityFunction.java:47) receives a CompileContext with:
  - `createNoiseSampler(Holder<NormalNoise>)`
  - `createRandom(Identifier)`
  - `createEndIslandRandom()` (deprecated)
  (DensityFunction.java:156-163).
- RandomState implements `createRandom` as `random.fromHashOf(seed)`, the world-seed positional random (RandomState.java:89-92). Noises come from `getOrCreateNoise` (RandomState.java:79-86, 120-122).
- Types are registered in DENSITY_FUNCTION_TYPE (core/registries/BuiltInRegistries.java:284-285; bootstrap at densityfunction/DensityFunctions.java:55).

- Read as `level-type`, lowercased with Locale.ROOT; the default is `minecraft:normal` (WorldPresets.NORMAL) (net/minecraft/server/dedicated/DedicatedServerProperties.java:139-142).
- **[corrected]** `WorldDimensionData.create` (DedicatedServerProperties.java:257-269):
  1. `Optional.ofNullable(Identifier.tryParse(levelType))`.
  2. Map it to `ResourceKey(WORLD_PRESET, id)`.

### 6. Vanilla client vs. server-only worldgen

#### Vanilla sync
- Vanilla only sends `RegistryDataLoader.SYNCHRONIZED_REGISTRIES` (net/minecraft/core/RegistrySynchronization.java:22-35; RegistryDataLoader.java:164-197). That list includes BIOME (165), DIMENSION_TYPE (183), BLOCK_TRANSFORMER (195) and BLOCK_STATE_PROVIDER (196), among others.
- noise_settings, noise, density_function, material_rule, world_preset and multi_noise_biome_source_parameter_list are WORLD_REGISTRIES only (RegistryDataLoader.java:98-114, 134). They are never sent.
- Biomes are sent with `Biome.NETWORK_CODEC`: climate settings, attributes and effects, with generation settings replaced by EMPTY (net/minecraft/world/level/biome/Biome.java:49-56).
- Entries not from a pack the client knows are sent in full (RegistrySynchronization.java:51-63). So custom data-driven biomes reach vanilla clients as data. Whether the client accepts them depends on their effects/attributes using only vanilla ids. That client-side decode is NOT VERIFIED.
- DENSITY_FUNCTION_TYPE is a static BuiltInRegistries registry (net/minecraft/core/registries/BuiltInRegistries.java:284-285). Vanilla does not sync it.

#### Fabric side (fabric-registry-sync-v0-8.0.5+1ca9f6365d.jar, bytecode only)
- `FabricRegistryInit.onInitialize` marks a fixed list SYNCED. DENSITY_FUNCTION_TYPE is not referenced. BLOCK_STATE_PROVIDER_TYPE is referenced but is not given SYNCED.
- `RegistrySyncManager.createAndPopulateRegistryMap`:
  - skips registries without SYNCED ("Not syncing registry: {}", offsets 396-421)
  - skips registries without MODDED (offsets 424-454)
  - **[corrected]** returns **null** when the resulting map is empty (offsets 733-745)
- `configureClient`:
  - returns early for the singleplayer owner (offsets 0-24)
  - returns early when the map is null (offsets 29-33)
  - only otherwise, disconnects a client lacking the Fabric sync channel, and only when `areAllRegistriesOptional(map)` is false (offsets 34-69)
- So a custom `karstscape:tower_field` type, used only inside server-side density_function/noise_settings, should not block a vanilla client. This is from bytecode, NOT VERIFIED at runtime. It also assumes no other installed mod adds entries to a SYNCED registry.

#### Caveats
- The mod must not add entries to SYNCED registries (block, item, etc.).
- It must not ship worldgen/block_state_provider (RegistryDataLoader.java:196) or block_transformer (RegistryDataLoader.java:195) entries that use custom types, because both registries are synced to clients.
