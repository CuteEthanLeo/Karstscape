## 不确定 / 需要你决定的

1. **Loom 版本**：我固定用稳定版 1.19.4，不跟模板的 `1.19-SNAPSHOT` 滚动更新，好处是构建可重复。如果你更想跟官方模板一致，可以改回去。
2. **SPEC §3.2 要随 26.3 调整的写法**（M2 才动手，先告知）：
   - `cache_2d` / `flat_cache` 已不存在。改为把峰顶高度做成 `domainAxes = X|Z` 的 2D 密度函数，编译器会自动每列只算一次，效果等同 2D 缓存。
   - 世界种子用 `CompileContext.createRandom(id)` 取得，和原版 `old_blended_noise` 同一种做法，不需要 mixin。
   - 放在 `interpolated` 外面、用 `max` 叠加的分支，会逐方块精确求值，所以石峰侧壁能保持垂直。
3. **M1 的群系接入方式**：`multi_noise_biome_source_parameter_list` 注册表只认原版硬编码的 overworld/nether 预设，所以 `karstscape:karstscape` 预设里的 biome source 必须写**内联 `biomes` 列表**。我打算用 `tools/` 下的脚本，以原版 7594 条参数（`reports/biome_parameters`）为底稿，加上 `KarstParams` 里的参数盒来生成这份列表。这样正好满足 SPEC“参数只写在一个地方”的要求。
4. **尚未实测的两点**（M1 会验证）：
   - Fabric `onInitialize` 中注册自定义密度函数类型，是否早于注册表冻结；
   - 原版客户端能否进入带自定义群系的服务器（需要你用官方启动器连一次）。
5. **自测脚本的一个已知行为**：专用服务器遇到未知的 `level-type` 不会报错，而是悄悄回落到 `minecraft:normal`。脚本会把这条回落 WARN 当成新增 WARN 判失败（已用不存在的预设实测，exit 4）。
6. **可选**：Windows Defender 会拖慢 `.gradle` 和世界存档的读写。要不要给项目目录加排除项由你决定，我不会改系统设置。
